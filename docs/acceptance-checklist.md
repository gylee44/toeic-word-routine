# 수용 기준 체크리스트

`docs/PRD.md` 10장(Acceptance Criteria)을 체크리스트로 옮긴 문서다. P0 항목을 모두 충족하면 MVP(1단계) 배포가 가능하다. `(P1)` 항목은 해당 기능을 구현한 경우에만 확인한다.

## 검증 현황 (2026-10-23)

| 표시 | 의미 |
|---|---|
| `[x]` | Supabase DB(스키마, RLS, 서버 함수)를 테스트 계정·테스트 단어로 직접 검증했다. 테스트 데이터는 롤백해 남기지 않았다. |
| `[ ]` | 화면(UI) 연동이나 배포 후에만 확인할 수 있거나, 아직 검증하지 못했다. 줄 끝에 DB에서 확인한 범위를 적었다. |

- 프론트엔드는 Supabase 연동을 마쳤고 `api.ts` 전 함수를 테스트 계정으로 검증했다. 다만 화면 기준 항목(모바일·데스크톱 표시, 흐름)은 브라우저에서 아직 모두 확인하지 못했다.
- 결제(AC-11)는 DB·Edge Function·화면 표시까지 확인했고, 결제창에서 끝까지 결제하는 성공 경로는 아직 확인하지 못했다.
- 운영 로그(AC-10)는 `/api/log` 수집 동작과 민감 값 가림을 개발 서버에서 확인했다. 배포 환경의 호스팅 로그 확인과 Edge Function 재배포는 남았다.
- `[x]` 항목도 화면에서 같은 결과가 나오는지 한 번 더 확인한다.

## AC-01. 인증

- [ ] 회원가입이 정상적으로 동작하고, 가입 시 프로필이 자동 생성된다. (DB: 가입 트리거로 프로필 생성, 이름이 없으면 이메일 앞부분 사용 확인 / 가입 화면은 연동 후)
- [ ] 유효한 계정으로 로그인할 수 있다.
- [ ] 잘못된 로그인 정보 입력 시 오류 메시지가 표시된다.
- [ ] 로그아웃 시 세션이 종료된다.
- [ ] 이미 가입된 이메일로 가입할 수 없다.
- [x] 일반 회원가입으로 관리자 권한을 얻을 수 없다. (기본 역할은 `user`, `profiles` 직접 수정 차단 확인)
- [ ] (P1) 소셜 로그인으로 가입·로그인할 수 있고, 신규 사용자는 온보딩으로 이동한다.

## AC-02. 온보딩

- [ ] 최초 로그인 시 온보딩 화면으로 이동한다.
- [ ] 목표 점수와 하루 학습량을 선택하지 않으면 시작할 수 없다. (DB: 허용되지 않은 점수·목표 값 거부 확인 / 화면은 연동 후)
- [x] 목표 점수에 따라 시작 구간이 FR-03 규칙대로 정해진다. (500·600·700·800·900점 매핑 확인)
- [ ] (P1) 더보기 화면에서 설정을 변경하면 홈 화면과 오늘의 학습에 반영된다. (DB: 목표 점수 변경 시 시작 구간과 하루 상한이 바뀌고 연속 학습일은 유지됨 확인 / 화면은 연동 후)

## AC-03. 단어 학습

- [x] 오늘의 학습이 시작 구간의 미학습 단어로 하루 목표 수만큼 구성된다.
- [ ] 카드 앞면·뒷면 전환이 정상 동작한다.
- [x] "알아요 / 모르겠어요" 선택 결과가 저장되고 규칙대로 복습일이 정해진다.
- [x] 학습 도중 나갔다가 돌아와도 응답한 카드 기록이 유지되고, 남은 단어부터 이어서 학습한다.
- [x] 하루 신규 학습이 40개를 넘지 않고, 목표 점수를 바꾸면 새 목표로 다시 40개까지 학습할 수 있다. 관리자 계정은 제한 없이 학습할 수 있다. (상한을 넘는 `record_flashcard` 직접 호출도 거부됨)
- [x] 추가 학습을 해도 연속 학습일(Day)이 늘지 않고, 목표 점수를 바꿔도 연속 학습일이 유지된다.
- [x] "알아요"를 고른 단어의 다음 복습일이 +1일과 +2일로 나뉜다. (40개 중 20개씩)

## AC-04. 퀴즈

- [x] 4지선다 보기가 정답 1개와 오답 3개로 구성되고, 오답은 가능한 한 같은 품사에서 선택된다.
- [x] 보기 중 중복되는 뜻이 없다. (같은 뜻의 단어를 여러 개 만들어 30회 반복 확인)
- [ ] 선택 즉시 정답/오답이 표시된다.
- [ ] 빠르게 여러 번 눌러도 응답이 한 번만 기록된다. (서버는 반복 호출을 기록으로 남기지만 단계는 하루 한 번만 올린다. 중복 기록 자체는 화면에서 막아야 한다)
- [ ] 퀴즈 결과 화면에 정답 수와 틀린 단어가 표시된다.
- [x] 퀴즈 결과가 복습 단계에 반영된다.

## AC-05. 복습 및 오답노트

- [x] 정답 시 복습 단계가 오르고 다음 복습일이 규칙대로 설정된다. (box 4 정답 시 `mastered`, 14일 뒤 복습)
- [x] 오답 시 복습 단계가 0으로 초기화된다.
- [x] 복습일이 도래한 단어만 "오늘의 복습"에 표시된다. (`mastered` 포함, 내일 이후 복습인 단어는 제외)
- [x] 틀린 단어가 오답노트에 표시된다.
- [x] 연속 2회 정답(서로 다른 날) 시 오답노트에서 제외된다. (같은 날 두 번 맞히면 남아 있고, 다음 날 맞히면 해제됨 확인)
- [x] 같은 날 같은 단어를 다시 맞혀도 복습 단계가 한 번만 오른다. (확인 퀴즈 4회 반복 시 box 1 → 2에서 멈추고 기록은 4건 남음, 다음 날 첫 정답은 다시 상승)
- [ ] (P1) 오답 단어만 다시 학습할 수 있다.

## AC-06. 홈 / 학습 기록

- [x] 오늘 학습 진행률이 오늘 처음 학습한 새 단어 기준으로 정확히 표시된다. (현재 목표 점수 기준)
- [x] 오늘 복습 대기 단어 수가 정확히 표시된다. (`mastered` 포함)
- [ ] 자정(KST)이 지나면 오늘 진행률이 0으로 초기화된다. (날짜는 KST 기준으로 계산하지만 자정 전환은 검증하지 못함)
- [x] (P1) 연속 학습일이 플래시카드·퀴즈 기록 기준, 하루 단위(KST)로 정확히 계산된다. (하루 건너뛰면 끊김, 오늘 기록이 없으면 어제부터 셈)
- [ ] 홈의 확인 퀴즈를 풀다 나갔다가 다시 들어오면 푼 문제 다음부터 이어 푼다. (v0.8)
- [ ] (P1) 단어장에서 학습한 모든 단어를 검색·필터·정렬할 수 있고, 학습 전 단어는 보이지 않는다. (v0.8)
- [ ] (P1) 플래시카드와 단어장에서 단어·예문 발음을 들을 수 있고, 미지원 브라우저에서는 발음 버튼이 숨겨진다. (v0.8)

## AC-07. 접근 권한

- [ ] 비로그인 상태에서 로그인이 필요한 페이지 URL로 직접 접근하면 로그인 페이지로 이동한다.
- [x] 비로그인 상태에서 API로 단어 데이터를 조회할 수 없다. (`anon`은 테이블 권한과 RPC 실행 권한이 없음)
- [x] 다른 사용자의 학습 기록, 오답 기록을 조회하거나 수정할 수 없다. (다른 사용자 세션에서 0행, 직접 쓰기 권한 없음)
- [x] API 요청을 직접 조작해도 복습 단계를 임의 값으로 바꿀 수 없다. (테이블 쓰기 권한이 없고 서버 함수로만 변경. 같은 단어로 퀴즈 응답을 반복해도 단계는 하루 한 번만 오름)
- [x] 일반 사용자는 단어 콘텐츠를 수정할 수 없다.

## AC-08. 콘텐츠 및 표기

- [ ] 랜딩 페이지와 더보기 화면에 TOEIC 상표 면책 문구가 표시된다.
- [ ] 서비스 내에 공식·출판사 기출 문제나 음원이 포함되어 있지 않다. (단어·예문은 오리지널 AI 초안이며 사람 검수 전)
- [ ] (P1) 더보기 화면에서 데이터 출처와 라이선스 표기를 확인할 수 있다. (`words.source`에 출처 저장됨 / 화면은 연동 후)

## AC-09. UI/UX

- [ ] 모바일 화면(세로, 375px 기준)에서 모든 핵심 기능을 사용할 수 있다.
- [ ] 데스크톱 화면에서도 정상적으로 표시된다.
- [ ] 화면 너비 320px ~ 1920px에서 가로 스크롤 없이 표시된다.
- [ ] 로딩 상태, 오류 메시지, 빈 화면이 정상적으로 표시된다.
- [ ] 가입부터 첫 학습·퀴즈 완료까지 핵심 시나리오가 정상 동작한다.

## AC-10. 배포 및 운영

- [ ] HTTPS 배포 URL에서 서비스에 접속할 수 있다.
- [ ] 배포 환경에서 어떤 경로든 새로고침해도 404가 나지 않는다.
- [ ] 배포 환경에서 회원가입·로그인이 동작하고, 인증 관련 링크(이메일 인증, 소셜 로그인 복귀)가 localhost가 아닌 배포 도메인으로 연결된다.
- [ ] 저장소와 브라우저 번들에 Supabase service role 키가 포함되어 있지 않다. (저장소 검색 결과 없음 / 배포 번들은 배포 후 확인)
- [ ] `main` 브랜치에 병합하면 자동으로 배포된다.
- [ ] PR에서 타입 검사와 빌드가 자동 실행되고, 실패 시 병합 전에 확인할 수 있다.
- [x] 브라우저에서 일어난 Supabase·Google 로그인·토스 결제 이벤트가 `/api/log`를 거쳐 한 줄 JSON으로 서버 로그에 출력된다. (개발 서버에서 `area`·`event`·`level` 출력, 잘못된 `area` 400 확인)
- [x] 로그에 비밀번호·토큰·인증 코드가 남지 않고 이메일·결제 키는 일부만 남는다. (`password`, `access_token` `[REDACTED]`, 이메일 `he***@test.com` 확인 / 토스 Secret 키는 코드에서 로그 대상이 아님)
- [ ] 배포 환경(Amplify)의 호스팅 로그에서 `area`·`sid`로 로그인·결제 흐름을 추적할 수 있다. (배포 후 확인)
- [ ] 결제 승인 Edge Function(`payments-confirm`)의 구조화 로그가 Supabase 로그에 보이고, 브라우저 로그와 `traceId`로 맞춰진다. (코드 수정 완료, 재배포 후 확인)
- [x] 데이터베이스 스키마·RLS·서버 함수가 마이그레이션 파일로 저장소에 포함되어 있다. (`supabase/migrations/` 9개)
- [ ] Demo Day용 데모 계정에 복습 대기 단어, 오답 단어, 연속 학습 기록이 준비되어 있다. (데모 계정 시드 미작성)

## AC-11. 결제 (v0.9)

- [ ] (P1) 더보기에서 Pro 이용권(1,000원, 30일)을 결제하면 결제 완료 후 하루 신규 학습 상한 없이 학습할 수 있다. (DB: Pro는 41번째 이후 새 단어 학습 가능, 비Pro는 41번째 P0001, 홈 `remaining_new` null 확인 / 실제 결제 흐름은 Secret 키 등록 후 확인)
- [ ] (P1) 이용 중에 다시 결제하면 남은 기간 뒤로 30일이 이어진다. (`complete_payment`로 정확히 +30일 확인 / 실제 결제는 미확인)
- [ ] (P1) 결제창을 닫거나 결제가 실패하면 안내 문구와 다시 시도 방법이 표시되고 Pro가 부여되지 않는다. (실패 화면 375·1440px 확인, URL의 message는 표시하지 않음 / 실제 결제창 취소는 미확인)
- [ ] (P1) 성공 URL의 금액을 바꾸거나 같은 승인 요청을 반복해도 Pro가 부여되지 않거나 한 번만 부여된다. (Edge Function: 금액 조작 400, 다른 사용자 주문 404, 가짜 토큰 401 확인. DB: 같은 승인 반복 시 기간 그대로 / 토스 승인 단계는 Secret 키 등록 후 확인)
- [x] (P1) 사용자가 주문 생성·상태 변경, `pro_until` 변경을 API로 직접 할 수 없고, 다른 사용자의 주문을 조회할 수 없다. (2026-10-22 테스트 계정 2개로 확인: 다른 사용자 주문 0행, `authenticated`의 insert·update·delete와 `pro_until` 수정은 42501, `anon` 조회 42501)
- [x] (P1) 저장소와 브라우저 번들에 토스 Secret 키가 포함되어 있지 않다. (10/22 빌드 결과물·저장소 검색 결과 없음, Client 키만 번들에 포함)
